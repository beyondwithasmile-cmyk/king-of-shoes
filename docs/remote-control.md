# リモートコントロールにつながらないとき

## 症状

- アプリで「新規」を押すと、チャットがPCではなくクラウドで始まる
  （PCのファイルやツールが使えない、`C:\KOS` が見つからない）。
- 前のチャットを開くと
  「The environment this session was running on has been deleted」と出る。

## 仕組み

1. アプリからPCを使うには、PCで受付サーバー（`claude remote-control`）が動いていて、
   それがアカウントに「接続先」として登録されている必要がある。
2. 受付サーバーが止まると、接続先は「到達不能」になる。
   長いあいだ戻らないと、接続先そのものが削除される。
3. 接続先が1つも無いと、「新規」はクラウドの環境（Default）で作られる。
   エラーにはならないので、気づきにくい。
4. 受付サーバーを起動し直すと、**新しい接続先**として登録される。
   消えた接続先の上で動いていたチャットは戻らない。

## 2026-10-15〜17 に起きたこと（日本時間）

| 時刻 | できごと |
| --- | --- |
| 10/15 1:11 | PCのチャットが普通に応答した最後 |
| 10/15 1:23 | 接続先が「到達不能」と記録される。受付サーバーが止まった |
| 10/15 1:57 | 新しく作ったチャットがPCに届かず、始まらないまま |
| 10/17 0:15 までに | 2日近く戻らなかったため、接続先が削除される |
| 10/17 0:18 | 「新規」で作ったチャットがクラウドで始まる |
| 10/17 0:20 | PCのスケジューラーは動いている（Heartbeat タブ、cycle 1） |
| 10/17 20:4x | PCで受付サーバーを起動すると「You must be logged in to use Remote Control」 |
| 10/17 20:45 | `claude auth login` でログインし直すと、残っていた受付サーバーがつながり直した |

原因は、**PCのClaudeのログインが切れたこと**と考えられる。
受付サーバーのプロセスは残っていたが、ログインが無いのでつながれなかった。
ログインが切れた理由はクラウドからは分からない。PCで調べる（下の「再発防止」）。

8月末から、接続先が入れ替わったのは今回で4回目（9/1ごろ、9/18ごろ、9/25、今回）。

## 直し方（PCで）

1. PCがスリープしていない、ネットワークにつながっていることを確かめる。
2. PowerShell で次を実行し、ブラウザでログインする。
   「You must be logged in to use Remote Control」と出るときは、ログインが切れている。

   ```
   claude auth login
   ```

   受付サーバーがまだ残っていれば、ログインのあと自動でつながり直す。
   次の手順で「This folder is already served by a terminal」と出たら、それが残っている印。
   もう1つ起動しなくてよい。
3. 受付サーバーが残っていないときは、`C:\KOS\KING_OF_SHOES_SYSTEM` に移って起動する。

   ```
   claude remote-control --name "KING of SHOES" --spawn=same-dir --capacity 5
   ```

   いつも付けている権限のオプションがあれば、それも付ける。
   PC側に起動用の道具（`tools/remote_control_*`）があるときは、そちらを使う。
4. アプリで「新規」を押し、接続先がPC（「KING of SHOES」または「DESKTOP-NMSPAKH…」）に
   なっていることを確かめてから始める。クラウド（Default）になっていたら切り替える。

### つながったかの確かめ方

- クラウドのチャットで「リモートコントロールの接続先を確認して」と頼む。
  `list_environments` に kind が `bridge` の接続先が出ていれば、受付サーバーは登録されている。
- 新規で作ったチャットに「今どこで動いている？」と聞き、`C:\KOS\KING_OF_SHOES_SYSTEM`
  が見えればPCで動いている。

## 再発防止

### このリポジトリでやっていること

`.claude/hooks/cloud-session-notice.sh`（SessionStart フック）が、
クラウドで始まったチャットにだけ「PCにつながっていない」と伝える。
チャットは最初の返答で、そのことと接続先の状態（`list_environments`）を知らせる。
黙ってクラウドで進むことはなくなる。ただし、受付サーバーが止まること自体は防げない。

### PCでやること

受付サーバーを止めないこと、止まっても自動で戻すことは、PCでしかできない。
PCで動くチャットに、次の依頼をそのまま渡す。

```
10/15 1:11〜1:23（日本時間）に、リモートコントロールの受付サーバー
（claude remote-control、名前「KING of SHOES」）が止まりました。
その後10/17まで自動で起動し直されず、接続先が削除されました。
10/17 に起動しようとすると「You must be logged in to use Remote Control」と出て、
claude auth login でログインし直したら、残っていた受付サーバーがつながり直しました。
原因を調べて、同じことが起きないように直してください。

調べること:
0. Claude Code のログインが、いつ・なぜ切れたか。
   見張りがログイン切れに気づけなかった理由。
1. Windows のイベントログ（システム）で、10/15 0:30〜2:00 とそれ以降の
   起動・シャットダウン・スリープ・復帰
   （Kernel-Power 41/42/107、EventLog 6005/6006/6008、User32 1074、
   Power-Troubleshooter 1）。
2. logs/remote_control_*.log、bridge-pointer.json、受付サーバーの見張りの記録で、
   同じ時間帯に何が起きたか。Claude Code の自動更新が走っていないか。
3. 見張りの予定タスク（タスク スケジューラ）が 10/15〜10/17 に動いたか、その結果コード。
4. なぜ見張りが受付サーバーを起動し直さなかったか。

直すこと:
- 受付サーバーが落ちた、接続先が消えた、PCが再起動した、のどの場合でも、
  数分のうちに受付サーバーが自動で上がるようにする。
- 見張りは「プロセスがあるか」だけでなく、「接続先が登録されているか」と
  「ログインが切れていないか」も見る。
- ログインが切れたときは、すぐ通知が届くようにする（ログインし直しは人にしかできない）。
- 上がらないときは通知が届くようにする。
- 直したあと、動いているチャットや予約が無いときに受付サーバーを止め、
  自動で戻ることを確かめる。
```

Windows の設定も確認する。

- 電源: スリープしない（電源接続時）。
- Windows Update: 使っている時間帯の設定、更新後の自動再起動。
- 再起動のあと、ログオンしなくても見張りが動くか
  （予定タスクの「ユーザーがログオンしているかどうかにかかわらず実行する」）。
- 停電のあとに自動で電源が入るか（BIOS の AC 復帰の設定）。
